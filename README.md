# J.U.R.A.

Персональный ассистент — «правая рука»: выполняет сложные задачи по команде, пишет код, работает с почтой, календарём,
банками и биржами, **не привязан ни к одной модели и ни к одному устройству**.

**Статус: v0.7.** Есть: зашифрованное хранилище и данные, резервные копии с восстановлением «после кражи», работа под паролем
(проверка пароля на сервере, вход на сайт через браузер — с твоего подтверждения), голос (слышит и говорит, локально),
**модели: Claude, OpenAI, Gemini и локальная — с жёсткими правилами, какие данные куда можно отправлять.**
Пока нет: диалогового ядра (агента), поэтому J.U.R.A. отвечает только на прямую команду `ask`. Планы — `docs/ROADMAP.md`.

Принцип проекта: **один путь — настоящий.** Демо-режима и подставных данных в продукте нет; подставные модели существуют только в тестах.

## Установка с нуля на «голый» Windows (один файл)

Скачай репозиторий (GitHub → Code → Download ZIP), распакуй и дважды щёлкни **`install.cmd`** (или в PowerShell: `.\install.cmd`).
Он сам: найдёт или поставит Python 3.12 (через winget) → создаст `.venv` → поставит проект и все библиотеки → предложит поставить
**Git** и **Ollama** (с твоего «да») → скачает браузер и модель речи → проверит целостность файлов и тесты → предложит создать хранилище
или восстановить его из копии. Журнал — `install.log` (команды и коды возврата, без секретов).

Флаги (после `install.cmd`): `--yes` (на вопросы о программах отвечать «да»; хранилище сам не создаёт), `--no-git`, `--no-ollama`,
`--skip-setup`, `--skip-tests`, `--restore ФАЙЛ.jurabak` (перенос на новый ПК: нужен файл копии и бумажный код),
`--backup-dir D:\JURA_backups`, `--github https://github.com/ВЛАДЕЛЕЦ/РЕПО.git` (привязать папку к репозиторию; пароли и токены сюда не вводятся — вход в GitHub спросит сам Git).
Запуск после установки: `jura.cmd shell`.

Нужен winget (на Windows 11 есть; на Windows 10 — «Установщик приложений» из Microsoft Store). Нет winget — установщик покажет ссылки и скажет, что поставить вручную.
Установщик **проверен только тестами с подставным запуском команд**; на настоящем чистом Windows его ещё никто не прогонял — первый запуск у владельца.

## Установка вручную (три команды)

Нужен Python 3.11+ и интернет. Открой папку проекта в VS Code, в терминале:

**Windows (PowerShell):**
```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e .
python -m jura setup
python -m jura init
```
**macOS / Linux:** `python3 -m venv .venv && source .venv/bin/activate`, затем те же `pip install -e .`, `python -m jura setup`, `python -m jura init`.

- `pip install -e .` ставит **всё** нужное (ядро, голос, браузерную автоматизацию) — ничего выбирать не надо, при смене ПК то же самое.
- `python -m jura setup` скачивает то, что pip поставить не может: браузер Chromium и модель распознавания речи, затем проверяет голос.
- `python -m jura init` создаёт хранилище и **бумажный код** — перепиши его от руки (подробнее `docs/VAULT.md`).

Если PowerShell ругается на запуск скриптов, выполни один раз: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.
VS Code спросит про интерпретатор — выбери `.venv`.

**Проверить, что код цел:** `python -m unittest discover -s tests` → должно быть **полное число тестов и `OK`** (сейчас 373).
Если красный `test_top_level_init_is_not_empty` или `test_source_files_match_the_shipped_manifest` — файлы испорчены при копировании: см. «Обновление» выше (`python scripts/check_files.py` покажет, какие).

## Обновление до новой версии (безопасный способ)

**Не копируй файлы по одному и не распаковывай «поверх»** — так уже терялось содержимое (`__init__.py` оказывался пустым, `voice.py`
подменялся одноимённым файлом из другой папки) и оставались файлы старых версий. Вместо этого:

1. Распакуй архив в **отдельную пустую папку** (например `C:\temp\jura-new`; лучше стандартным «Извлечь всё» Windows).
2. В терминале VS Code, в папке своего проекта (с активным `.venv`):
```
python scripts/update_from.py C:\temp\jura-new
```
Скрипт сам проверяет, что архив распакован правильно, показывает план (что обновится, добавится и будет удалено как остаток старых версий)
и применяет его только после твоего «да». `.venv`, `.git` и данные в `~/.jura` он не трогает.
3. Затем: `pip install -e .`, `python -m unittest discover -s tests`, `python scripts/check_files.py` (должно быть «всё совпадает»).

**Один раз, если в твоём проекте ещё нет папки `scripts` (первое обновление после v0.6):** распакуй архив в отдельную папку и выполни **из неё**:
```
cd C:\temp\jura-new\jura
python scripts/update_from.py . --project "D:\путь\к\твоему\проекту"
```
`python scripts/check_files.py` в любой момент показывает, что в проекте изменено, пусто, отсутствует или лишнее. Красный
`test_source_files_match_the_shipped_manifest` в тестах означает то же.

## Git и GitHub (один раз)

Без Git любую мою правку нельзя посмотреть как «что именно изменилось» и нельзя откатить. Поставь Git (git-scm.com), затем в папке проекта:
```
git init
git add .
git commit -m "baseline v0.5"
```
(В VS Code то же: значок Source Control → Initialize Repository → Commit.) Если Git попросит имя: `git config --global user.name "Имя"` и
`git config --global user.email "почта"`.

Дальше после каждого моего архива: распаковал поверх → в Source Control видны изменённые файлы и построчные различия → смотришь →
коммитишь (`git commit -am "v0.6"`). Не понравилось — `git restore .` возвращает всё как было. Пустой/испорченный файл виден сразу.

### GitHub — резервная копия кода и автоматическая проверка
1. На github.com: **New repository** → имя `jura` → **Private** → *ничего не добавляй* (ни README, ни .gitignore, ни license) → Create.
2. В папке проекта (после `git commit` выше):
```
git remote add origin https://github.com/ТВОЙ_ЛОГИН/jura.git
git branch -M main
git push -u origin main
```
При первой загрузке Git (Credential Manager, ставится вместе с Git for Windows) откроет браузер для входа. **Пароли и токены в файлы и в чат не клади.** Включи двухфакторную защиту в GitHub.
3. Во вкладке **Actions** на GitHub после каждой загрузки автоматически запускаются тесты (Windows и Linux, Python 3.11–3.13) — зелёная галочка означает, что всё цело.
   Файл проверки я проверить не мог (у меня нет GitHub) — если упадёт, пришли вывод.
4. **В GitHub попадает только код.** Данные (`~/.jura`) лежат вне проекта, а `.gitignore` исключает `.venv`, `*.vault`, `*.db`, `*.jurabak`, `.env` (тест следит, чтобы это не пропало). Данные защищены зашифрованными копиями на втором диске, а не GitHub.
5. **Я не могу войти в твой репозиторий** (и токены мне присылать нельзя). Показать мне состояние: архив `git archive --format=zip -o ../jura-clean.zip HEAD`, либо вывод `git log --oneline -15` и `git diff --stat`.
   Публичный репозиторий я мог бы читать по ссылке, но там окажется модель угроз со всеми известными слабостями — пока не советую.

**Присылая мне архив, не клади в него `.venv`** (он весит сотни МБ и не нужен). Чистый архив из Git: `git archive --format=zip -o ../jura-clean.zip HEAD`.

## Первая проверка вживую

Не клади самые важные пароли: пока Core живёт на твоём повседневном ПК, это лабораторный режим (`docs/THREAT_MODEL.md`).

**1. Папка для копий** — на другом физическом диске (PowerShell): `setx JURA_BACKUP_DIR "D:\jura-backups"`, затем перезапусти терминал.

**2. Секреты, память, копия**
```
python -m jura shell
jura> secret set spotify          ← значение вводится скрыто
jura> secret get spotify
jura> memory add Моя любимая музыка — джаз
jura> memory search джаз
jura> leak-check ПАРОЛЬ           ← ищет в открытом виде во ВСЕХ файлах: должно быть «Не найдено»
jura> backup                      ← зашифрованная копия на второй диск
jura> exit
python -m jura peek-raw           ← что видит взломщик без ключа
```
**3. «Украли компьютер»:** переименуй `~/.jura` и восстанови: `python -m jura restore D:\jura-backups\ФАЙЛ.jurabak --to C:\Users\ТЫ\.jura-new`
(на вопрос про пароль нажми Enter, введи бумажный код — ввод скрыт), затем `$env:JURA_HOME="C:\Users\ТЫ\.jura-new"; python -m jura secret-get spotify`.

**4. Модели** (подробно — `docs/MODELS.md`). Приватные данные (по умолчанию всё, что ты вводишь) идут **только на локальную модель**; облако — только для того, что ты сам пометил открытым (`--zone O`):
```
jura> secret set anthropic.api_key        ← ключ из консоли провайдера (или openai.api_key / gemini.api_key)
jura> model discover anthropic            ← актуальные имена моделей, доступные тебе
jura> model add claude anthropic ИМЯ --quality 9
jura> model test claude
jura> ask --zone O Объясни, что такое прерывание
jura> model add local-main local ИМЯ --context 8192     ← после установки Ollama и `ollama pull`
jura> ask --zone P Составь план на завтра
```
**5. Работа под паролем.** По умолчанию всё запрещено — сначала разреши. Действия с паролями требуют **повторного ввода пароля хранилища** каждый раз.
Проверка на публичном тестовом сервисе (если httpbin.org не отвечает — `httpbingo.org`):
```
jura> secret set demo.username            ← user
jura> secret set demo.password            ← pass123
jura> tools
jura> policy enable http.basic            ← спросит пароль хранилища
jura> run http.basic_check url=https://httpbin.org/basic-auth/user/pass123 secret=demo
      … Введи пароль хранилища для подтверждения (Enter — отмена):
✓ HTTP 200: логин и пароль приняты
```
С неверным паролем (`secret set demo.password` ещё раз) — `HTTP 401`. После `run` показываются **метки результата** (зона, доверие, источник).

**Вход на сайт через браузер** (видимое окно; после `setup`):
```
jura> site add мойсайт https://адрес-страницы-входа "#селектор-логина" "#селектор-пароля" "#кнопка" --ok-url часть-адреса-после-входа
jura> secret set мойсайт.username
jura> secret set мойсайт.password
jura> policy enable web.login
jura> run web.login site=мойсайт
```
Пароль вводится **только на адресе из профиля** (и перечисленных в `--allow-origin`): если сайт перенаправил на другой адрес, вход отменяется
до ввода. Селекторы — через «Просмотреть код» (F12). **С настоящим браузером эта часть проверяется впервые у тебя** — присылай ошибки.
Подробности и честные оговорки — `docs/OPERATING.md`.

## Голос (локально, приватно)
```
python -m jura voice-check            ← диагностика по пунктам
python -m jura listen                 ← Enter, говори, Enter → текст и скорость распознавания
python -m jura speak "Привет, я Юра"
python -m jura echo                   ← повторяет услышанное; «стоп» — выход
```
Микрофон: Параметры Windows → Конфиденциальность → Микрофон → разреши классическим приложениям. Подробности — `docs/VOICE.md`.
**Микрофон и модель впервые встречаются с этим кодом на твоём ПК** — присылай вывод `voice-check`.

## Команды

| Команда | Что делает |
|---|---|
| `setup` | Скачивает Chromium и модель речи, проверяет голос (после `pip install -e .`) |
| `init` | Создаёт хранилище, зашифрованные базы и **бумажный код** |
| `shell` | Интерактивная оболочка: пароль один раз, дальше все команды ниже (в ней `help`) |
| `secret-set / -get / -list / -delete ИМЯ` | Пароли и ключи (зона S2, зашифрованное хранилище) |
| `memory-add ТЕКСТ [--zone O\|P\|S1]`, `memory-search СЛОВА` | Память (зашифрована по зонам) |
| `tools`, `policy list\|enable\|disable`, `run ИНСТРУМЕНТ ключ=значение …` | Что умеет, что разрешено, выполнить |
| `site add\|list\|show\|delete …` | Профили сайтов для входа через браузер |
| `backup [--to ПАПКА] [--keep N]`, `backup-list` | Зашифрованные копии на другой диск |
| `backup-verify ФАЙЛ`, `restore ФАЙЛ --to ПАПКА` | Проверка и восстановление |
| `change-passphrase`, `new-recovery-code`, `vault-check-recovery` | Смена пароля (с повышением стойкости), новый бумажный код, «учения» |
| `leak-check ТЕКСТ`, `peek-raw`, `verify-log`, `status` | Проверки: нет ли текста в открытом виде, что видит взломщик, целостность журнала |
| `model list\|add\|remove\|discover\|test`, `ask` | Модели (облачные и локальная) и вопрос к ним; правила зон соблюдает роутер |
| `voice-check`, `listen`, `speak`, `echo` | Голос |

Данные — в `JURA_HOME` (по умолчанию `~/.jura`), копии — в `JURA_BACKUP_DIR`. Перед реальным использованием прочитай `docs/VAULT.md` и `docs/BACKUP.md`.

## Карта проекта

```
src/jura/
  contracts/      общие типы и интерфейсы — ни от чего не зависят
  kernel/         стабильное ядро: журнал, задачи, политики, инструменты, шифрование, хранилище, брокер секретов, копии
  runtime/        изменчивая логика: роутер моделей (правила зон)
  adapters/       заменяемые реализации: память, модели (Claude, OpenAI, Gemini, локальная), коннекторы, голос
  app.py          сборка ядра            session.py   разблокированная сессия       model_registry.py   настройка моделей
  voice.py        голосовой контур       cli_shell.py / cli_standalone.py / __main__.py   консоль (разнесена на три файла)
tests/            373 теста: логика, шифрование, границы слоёв, защита от утечек; leak_check.py — проверка соединений SQLite
docs/             архитектура, модель угроз, ADR, диаграммы
```

## С чего начать чтение кода
1. `src/jura/contracts/types.py` — словарь проекта: зоны данных, риск, принципалы, `ToolResult`.
2. `src/jura/kernel/policy.py` — «кто, что и когда может». Самый важный файл.
3. `src/jura/kernel/tools.py` — единственный путь вызова любого инструмента.
4. `src/jura/runtime/router.py` — куда можно отправлять данные (какая модель).
5. `src/jura/session.py` — как всё соединено. Шифрование: `docs/adr/0008-…md`, затем `kernel/keyring.py`.
