# J.U.R.A. — контекст проекта для Claude

Персональный ассистент («правая рука», в духе Джарвиса). Владелец — единственный пользователь.
Сам код не пишет, но читает и понимает. Код пишет Claude. Среда: Windows 11, VS Code, PowerShell.
Источник: диалог проектирования на claude.ai (29.09–13.10.2026), продолжение здесь, в Claude Code.

## Конечная цель
- По команде (текст и голос) выполняет сложные задачи и пишет код в реальном времени.
- Работает с почтой, календарём, банками и Binance. Переводы денег — только с подтверждением Face ID на iPhone.
- Сам инициирует задачи, но только в рамках явных, отзываемых разрешений (Standing Orders).
- Не зависит от моделей: Claude, OpenAI, Gemini и локальные модели — заменяемые инструменты.
- Не привязан к устройству: переносится со всей памятью на новую технику; телефон, ПК и ноутбук работают одновременно как узлы.
- Личные данные зашифрованы. Ключ восстановления есть только у владельца — бумажный код.

## Принципы работы с владельцем (важно)
- **Никаких demo-режимов.** Сразу реальный режим и реальные данные, проблемы чиним по ходу. Подставные модели живут только в `tests/fakes.py`, тест не пускает `fake*`/`demo*` в продукт.
- **Одна команда установки:** `pip install -e .` без extras вроде `.[voice]`. Всё, что pip не ставит, скачивает `python -m jura setup`. На чистом Windows — `install.cmd`.
- **Простота кода = надёжность.** Сложность — в архитектуре, а не в коде. Стандартная библиотека, внешние зависимости только через ADR (сейчас: `cryptography`, плюс опциональные голос и Playwright).
- **Качество важнее скорости**, времени у проекта много.
- Честно говорить, что проверено живьём, а что только тестами с подставными библиотеками.
- **Процесс (с 13.10.2026):** Claude правит проект прямо в `D:\J.U.R.A` через Claude Code: тесты → манифест → коммит с понятным описанием. **Push на GitHub — только по команде владельца.** Архивы и ручное копирование файлов больше не используются.
- Общение на русском.

## Стек и архитектура
- Python 3.11+ (целевой 3.12), модульный монолит. Слои, зависимости идут только вниз (проверяет `test_architecture`):
  `app/__main__` → `runtime` (изменчивое: роутер моделей, агенты) → `kernel` (стабильное: журнал событий, задачи, политики, tools, хранилище секретов) → `adapters` (модели, память) → `contracts` (типы и интерфейсы, ни от чего не зависят).
- Контракты языконезависимые. Критичные части (Policy, Vault, Finance) проектируются как отдельные процессы, чтобы позже их можно было переписать на Go или Rust.
- Диаграммы архитектуры v4.1 — в `docs/diagrams/`. Решения записаны в ADR (`docs/adr/`).

## Безопасность (не ослаблять)
- Риск-уровни L0–L3. L2 — подтверждение владельца; L3 (деньги, замки, необратимое) — только Face ID на телефоне (подпись Secure Enclave). Голос и консоль L3 не подтверждают. Автономный J.U.R.A. L3 делать не может, L2 только предлагает.
- Политика проверяется на каждом вызове инструмента (Tool Broker, PEP/PDP). Учитываются принципал, устройство, уровень аутентификации и действие.
- Зоны данных: **O** — облако и локальная модель; **P** и **S1** — только локальная модель (127.0.0.1/localhost); **S2** (пароли, ключи) — никакой модели. В облако P пойдёт только через Redaction Gateway, которого ещё нет. Правило жёсткое, `--model` его не обходит.
- Недоверенный контент (письма, страницы) не может запустить действие. `ToolResult` несёт зону, доверие и источник; метки нельзя ослабить.
- Шифрование AES-256-GCM: журнал, задачи, память, секреты, бэкапы. Иерархия ключей: пароль (вводится один раз при старте) или бумажный код (256 бит) → главный ключ → ключи зон. Цепочка хэшей журнала — tamper-evident, якорь хранится вне Core.
- Пароли подставляет код, а не модель. Адрес входа берётся из профиля сайта, только https; перед вводом пароля сверяется адрес страницы. CredentialBroker — у каждого коннектора свой список разрешённых секретов.
- Хранение: код — на GitHub (приватный репозиторий), память — **никогда не в git**. Бэкапы `.jurabak` по правилу 3-2-1: `JURA_BACKUP_DIR` на втором диске D: (1 ТБ), позже облако (restic) и USB.
- Данные вне проекта: `~/.jura`. Пока Core живёт на повседневном ПК, реальные важные секреты и деньги туда не класть.

## Железо владельца
Ryzen 5 2600, GTX 1660 Ti 6 ГБ. Локальные LLM класса 3–8B в квантовании через Ollama.
Голос: STT — GigaAM v3 (onnx-asr, CPU, русский), TTS — голоса Windows. Речь обрабатывается локально.

## Состояние на 13.10.2026 (v0.7.0 / коммит «v0.7.1»)
Готово: ядро, шифрование и бэкапы (v0.2), работа под паролем и `web.login` через Playwright (v0.3), локальный голос `listen`/`speak`/`echo`/`voice-check` (v0.4), удаление demo и исправления по ревью (v0.5), адаптеры Claude/OpenAI/Gemini/локальной модели с командами `model …` и `ask` (v0.6), проверка целостности `MANIFEST.sha256` + `scripts/check_files.py` + `scripts/update_from.py` (v0.6.1), установщик `install.cmd` / `scripts/install.py` / `bootstrap.ps1` (v0.7.0). Всего 373 теста.

**Живьём не проверено:** голос с микрофоном, Playwright, облачные модели, Ollama, GitHub Actions (`.github/workflows/tests.yml`), установщик на чистом Windows.

**Заметки:**
- `commands.txt` в корне — личный список команд владельца. **Не трогать и не удалять.**
- Раньше при ручном копировании портились `src/jura/__init__.py` (обнулялся) и `src/jura/voice.py` (подменялся `contracts/voice.py`). Теперь это ловят тесты и `check_files.py`.
- После правок в `src/`, `tests/`, `docs/`, `scripts/` и корневых файлах из манифеста пересоздавать манифест: `python scripts/make_manifest.py`, иначе `check_files.py` и тест целостности покраснеют.
- В Git Bash вывод Python идёт в cp1251, поэтому запускать с `PYTHONIOENCODING=utf-8` (с `-I` — через `-X utf8`).

**Расхождения с диаграммой v4.1 (осознанные или пока не закрытые):**
- Хранилище — SQLite за интерфейсами, а не PostgreSQL (ADR-001: Postgres появится адаптером).
- Трассировка и evals на диаграмме заявлены «с первого дня» (стр. 07), а в коде их ещё нет.
- Ожидающие подтверждения живут в памяти процесса (`app.py`) — durable-версия в планах Phase 1.
- Голос сделан раньше инфраструктуры (на стр. 12 голос — Phase 3, после Core-сервера).
- ADR-007 (изоляция плагинов), ADR-009 (версии событий), ADR-010 (трейсы и опыт) из очереди на стр. 13 ещё не написаны.
- `docs/ARCHITECTURE.md` и `docs/ROADMAP.md` частично устарели: там написано «реальных моделей пока нет» и не отмечены адаптеры в Phase 1, хотя они сделаны в v0.6.

**Решения владельца (13.10.2026):**
- Облачный провайдер: **пока только локальные модели** (Ollama). Облако не подключаем.
- Код самого J.U.R.A. (репозиторий) — **зона O**, его можно показывать облачным моделям. Личные данные и `~/.jura` остаются приватными.
- Следующий шаг: **живая проверка** на ПК владельца — голос, Ollama, пароль от неважного сервиса, установщик.
- Ещё не решено: месячный лимит расходов на API (станет нужен, когда подключим облако).

## Дорожная карта (следующие шаги)
1. Владелец проверяет живьём: голос, Ollama и `ask --zone P`, облачный ключ и `ask --zone O`, пароль от неважного сервиса.
2. v0.8 — зоны по источникам («этот проект открытый, эта папка личная»).
3. Диалоговое ядро v0: текст → модель → инструменты через политики, бюджеты расходов, трассировка. Затем голос по смыслу.
4. Redaction Gateway (сканер секретов и очистка приватного контекста перед облаком).
5. Dev-ассистент: песочница для кода, проверка тестами, подтверждение перед слиянием.
6. Надёжное исполнение (подтверждения и задачи переживают перезапуск), evals.
7. Дальше: отдельный сервер для Core (TPM, Windows Hello или YubiKey), почта и календарь через официальные API, инициатива J.U.R.A., банк на чтение, Face ID на iPhone, деньги — в самом конце.
