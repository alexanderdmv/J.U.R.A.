# Правила работы над J.U.R.A.

## Роли
- **Код пишет Claude.** Ты читаешь, задаёшь вопросы, принимаешь решения. Писать код тебе не нужно.
- Каждое изменение сопровождается тремя вещами: **что изменено, зачем, как проверить**.
- Если что-то в коде непонятно — это дефект кода, а не твой. Проси переписать проще.

## Один путь — настоящий
В продукте нет демо-режима, подставных данных и подставных моделей. Подставные модели, серверы и драйверы живут **только в `tests/`**
(`tests/fakes.py`, `tests/localservers.py`). Новая возможность сразу работает на настоящих данных; ошибки чиним по ходу.
Тест `test_project_integrity` не даст вернуть `fake*`/`demo*` в `src/`.

## Обновления и целостность
- Новая версия приходит архивом с `MANIFEST.sha256` (хэши всех файлов). Обновление — только через `python scripts/update_from.py ПАПКА`
  (проверяет распаковку, показывает план, удаляет остатки старых версий). **Файлы по одному не копировать.**
- `python scripts/check_files.py` — сверка проекта с манифестом в любой момент.
- В архивах, которые пересылаются, не должно быть `.venv` (сотни МБ). Чистый архив: `git archive --format=zip -o ../jura-clean.zip HEAD`.
- Тот, кто собирает архив, пересоздаёт манифест последним шагом: `python scripts/make_manifest.py`.

## Принципы кода
1. **Простота важнее изящества.** Короткие функции, без метапрограммирования и «умных» трюков.
2. **Типы везде.** Подсказки типов в каждой сигнатуре.
3. **Комментарии объясняют «зачем», не «что».** На русском. Имена — английские.
4. **Ядро — только стандартная библиотека.** Новая зависимость = отдельный ADR.
5. **Один путь для опасного.** Инструменты вызываются только через `ToolPort`; модели — только через `ModelRouter`.
6. **Ошибки — явные** (`contracts/errors.py`). Никаких молчаливых `except: pass`.

## Безопасность (нарушать нельзя)
- Всё, что попадает на диск, шифруется через `Cipher` (контракт `contracts/crypto.py`); открытый текст в базах недопустим.
- Секреты — только в Vault. Никогда в коде, логах, промптах, тестах (только фиктивные значения).
- В журнал пишутся имена, хэши и метки — **не значения аргументов и не тексты запросов**.
- S2 не попадает ни в одну модель и не хранится в памяти. S1 — только в локальные модели.
- Новые возможности включены **выключенными**: сначала default deny, потом явное разрешение.

## Процесс
- **Ядро меняется через ADR** (`docs/adr/`): контекст, решение, альтернативы, последствия.
- **Каждое изменение — с тестом.** Красные тесты = работа не закончена.
- **Контракты v1 замораживаются после walking skeleton**, не раньше. Дальше — только через ADR.
- Рекомендуется `git init` и маленькие коммиты — тогда любое изменение можно откатить.

## Чек-лист читателя: что проверять в изменениях
- [ ] Понятно ли мне, что делает каждая новая функция? Если нет — просить упростить.
- [ ] Нет ли новой зависимости? Есть ли на это ADR?
- [ ] Не обходит ли код `ToolPort` / `ModelRouter` / `Vault`?
- [ ] Не пишутся ли в лог значения данных, а не только имена и хэши?
- [ ] Есть ли тест, который упал бы, если бы это поведение сломалось?
- [ ] Включено ли новое действие по умолчанию? (должно быть выключено)
- [ ] Прошёл ли `python -m unittest discover -s tests`?

## Definition of Done для фазы
Тесты зелёные (`python tests/leak_check.py` — «НЕ закрыто: 0») · `git commit` с понятным сообщением · `docs/ARCHITECTURE.md` и `THREAT_MODEL.md` обновлены ·
новые решения записаны в ADR · восстановление из бэкапа проверено (с Phase 2).
