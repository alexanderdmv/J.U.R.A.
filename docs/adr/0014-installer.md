# ADR-014 — Установщик для нового компьютера
**Статус:** Accepted; дополнен ADR-016 — установка без winget (прямые официальные установщики), VC++ Runtime, папки в jura.local.json

## Контекст
Железо будет меняться. Перенос должен быть: скачал репозиторий — запустил один файл — всё стоит (Python, Git, Ollama, библиотеки, браузер, модель речи).

## Решение
- Два уровня: `install.cmd` → `scripts/bootstrap.ps1` (единственное, что работает без Python: находит Python 3.11+ или ставит через winget) → `scripts/install.py` (вся логика на Python, тестируется).
- Менеджер пакетов Windows — **winget**; ставятся только `Git.Git`, `Ollama.Ollama`, `Python.Python.3.12` и **с согласия пользователя** (`--yes` — заранее «да»). Нет winget — ссылки для ручной установки, не ошибка.
- Все внешние действия (запуск, поиск программ, ввод, платформа) подаются в `Installer` снаружи → тесты без реальной системы.
- **Секретов установщик не касается:** пароль и бумажный код вводятся только в `jura init` / `jura restore`; `--yes` хранилище не создаёт; адрес GitHub с логином/токеном отклоняется; в `install.log` — только команды и коды.
- `bootstrap.ps1` и `.cmd` — только ASCII (Windows PowerShell 5.1 читает UTF-8 без BOM как ANSI); окончания строк CRLF (`.gitattributes`).
- Установщик расширяется добавлением записей в `WINGET_PACKAGES` и шагов в `Installer.main`.

## Альтернативы
- Скачивать и запускать скрипт из интернета одной строкой (`irm | iex`): удобно, но запуск непроверенного кода; выбран скрипт из репозитория, который владелец видит.
- Собственный .exe-установщик: избыточно на этом этапе.

## Последствия
- Python в системе ставится до проверки целостности файлов (скрипт `bootstrap.ps1` — единственная непроверяемая тестами часть, поэтому он короткий).
- Версии Git/Ollama — «последние»; воспроизводимость версий — lock-файл позже (замечание ревью №13).
