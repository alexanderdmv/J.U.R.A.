# ADR-003 — Модель авторизации и политик
**Статус:** Accepted (реализовано в `kernel/policy.py`)

## Контекст
«Пользователь = можно всё» — неверная модель. Команду мог дать ты, а мог — текст из письма; на телефоне с Face ID
и в машине по голосу — разный уровень уверенности.

## Решение
Права = **принципал + устройство + уровень аутентификации + запрошенное действие**.
- Принципалы: `USER`, `JURA` (автономно), `TRIGGER`, `EXTERNAL` (никогда не исполнитель).
- Уровни риска L0–L3 заданы в `ToolSpec`, а не решаются моделью.
- **Default deny:** capability должна быть явно включена в `PolicyConfig`.
- L0 — свободно. L1 — нужна аутентификация устройством. **L2/L3 — всегда подтверждение конкретного действия.**
- Подтверждение (`Approval`) привязано к **хэшу вызова**, живёт 120 с, должно иметь достаточную силу
  (`L3 → BIOMETRIC`) и прийти с достаточно доверенного устройства (`L3 → tier HIGH`).
  Команда может быть дана из машины, а подтверждена Face ID на телефоне.
- Автономные принципалы: L3 запрещён; L2 превращается в предложение.
- Недоверенный контент в контексте (taint) всегда требует человека для L2+.
- **Изменение политики — привилегированная операция:** только `USER` + физический ключ; пишется в журнал.

## Face ID (план, Phase 2–3)
Face ID сам по себе на сервер не передаётся. Телефон (приложение или PWA с passkey) после Face ID подписывает
ключом из Secure Enclave хэш вызова; Core проверяет подпись и создаёт `Approval(auth=BIOMETRIC, device=phone)`.

## Дополнение (v0.3): временный уровень PASSPHRASE
Физического ключа (YubiKey) пока нет, а менять политику с консоли нужно. Добавлен уровень `AuthLevel.PASSPHRASE`
(повторный ввод пароля хранилища «прямо сейчас», между DEVICE и BIOMETRIC). `PolicyConfig.change_min_auth` задаёт,
чем подтверждается смена политики: по умолчанию `HARDWARE_KEY`, а консольная сессия **временно** ставит `PASSPHRASE`.
Каждая такая смена пишет события `policy.reauth` (с пометкой «временно») и `policy.changed`.
**Когда появится YubiKey — вернуть `HARDWARE_KEY`.** PASSPHRASE не заменяет Face ID: для L3 по-прежнему нужен BIOMETRIC
на доверенном устройстве, поэтому деньги из консоли невозможны.

## Дополнение (v0.5): использование паролей
`ToolSpec.uses_credentials=True` поднимает требование к подтверждению до `PASSPHRASE`: «да» с разблокированной консоли недостаточно,
пароль хранилища вводится заново при каждом выполнении (проверяется `Vault.verify_passphrase`). Это не криптографическое подтверждение
намерения (его даст Face ID → Secure Enclave), но убирает случайные и «автоматические» использования паролей. Инструмент, использующий
пароли, требует подтверждения даже при риске L1.
