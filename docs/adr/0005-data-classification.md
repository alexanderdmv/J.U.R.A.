# ADR-005 — Классификация данных и зоны
**Статус:** Accepted (реализовано частично)

## Решение
Единая шкала (раньше было две): **O** (открытое) · **P** (приватное, по умолчанию) · **S1** (чувствительное) · **S2** (учётные данные).
- S2: ни одна модель не видит; в память не пишется; живёт в Vault; обрабатывается детерминированным кодом.
- S1: только локальные модели; инструменту — только если его `max_zone ≥ S1`.
- P: **только локальные модели.** Облако для P допустимо лишь через Redaction Gateway — он обязан превращать очищенный контекст в НОВЫЙ контекст зоны O. Пока Gateway не реализован, это правило **жёстко соблюдает роутер** (v0.5; раньше P ошибочно уходило в облако).
- **Зона определяется не типом данных**, а правилами: default policy (P) + явные метаданные + политика источника + решение владельца.
- Производные данные наследуют **максимальную** зону источников (`max_zone`).
- Проверка не доверяет «паспорту» модели: S1 не уйдёт нелокальной модели, даже если она заявила иное.

## Реализовано
Типы и наследование, фильтры в роутере, инструментах и памяти. **Не реализовано:** реестр политик источников,
ручное переопределение зоны (повышать можно свободно, понижать — только с подтверждением), Redaction Gateway.

## Дополнение (v0.5): метки результатов инструментов
Результат любого инструмента — `ToolResult(data, zone, trust, source)`. Без меток письмо (зона P, недоверенное) превратилось бы в обычный
текст и могло бы уйти в облако. `ToolSpec` задаёт минимальные метки (`result_zone`, `result_trust`); по умолчанию — **P и недоверенное**.
Обработчик может сделать метки строже, но не мягче. Потребитель (будущее диалоговое ядро) обязан брать зону запроса к модели из меток
данных (`max_zone`), а доверие — из `trust` (недоверенное остаётся «заражённым» при L2+).
