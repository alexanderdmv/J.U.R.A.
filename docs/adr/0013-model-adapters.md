# ADR-013 — Адаптеры моделей и локальная среда запуска
**Статус:** Accepted (реализовано в v0.6; с настоящими сервисами не проверено)

## Контекст
Нужны и облачные модели (Claude, OpenAI, Gemini), и локальная (владелец: GTX 1660 Ti 6 ГБ, данные P/S1 только локально), без привязки
ядра к какой-либо из них.

## Решение
- **HTTP на стандартной библиотеке, без SDK провайдеров.** Меньше зависимостей и скрытого поведения; каждый запрос виден в коде.
  Общий слой (`adapters/models/http.py`): только https, редиректы не выполняются (ключ не уйдёт на другой сервер), ключ и текст запроса не попадают в ошибки.
- **Один адаптер «OpenAI chat completions» для облачного OpenAI и локальных серверов** (Ollama, LM Studio, llama.cpp): различие в настройках —
  `max_completion_tokens` против `max_tokens`, ключ, допустимая зона данных.
- **«Локальная» модель обязана быть на этом компьютере** (127.0.0.1/localhost/::1), проверяется при создании: иначе чужой сервер мог бы получать S1.
- **Ключи API** — в хранилище (`anthropic.api_key`, `openai.api_key`, `gemini.api_key`), читаются только через `CredentialBroker` своим провайдером.
- **Настройка моделей** — зашифрованная запись `__models__` в хранилище; одна испорченная запись не ломает остальные.
- **Правила зон — в роутере и не настраиваются** (ADR-005). `--model` их не обходит. Запрос проверяется на размер окна контекста.
- Первая локальная среда — **Ollama** (простая установка на Windows, OpenAI-совместимый интерфейс).

## Альтернативы
- SDK провайдеров: удобнее, но десятки зависимостей и собственная сетевая логика.
- Встроенный llama.cpp (llama-cpp-python): сборка на Windows сложнее; можно добавить позже тем же интерфейсом.

## Последствия
- Нет потокового вывода, вызова инструментов моделью и учёта расходов (бюджеты — Phase 1).
- Имена моделей не зашиты (меняются часто): `model discover`.
- На 6 ГБ локальная модель класса 3–4B: все приватные задачи ограничены её возможностями, пока нет зон по источникам и Redaction Gateway.
