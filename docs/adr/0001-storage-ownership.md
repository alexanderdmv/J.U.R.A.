# ADR-001 — Роли хранилищ: состояние и история
**Статус:** Accepted

## Контекст
На диаграммах и PostgreSQL, и Event Log назывались «источником истины» — двусмысленность.

## Решение
- **Таблицы (сегодня SQLite, позже PostgreSQL) = авторитетное ТЕКУЩЕЕ состояние** (задачи, outbox, память).
- **Event Log = авторитетная ИСТОРИЯ** (что, кто, когда решил и сделал).
- Состояние и событие пишутся **одной транзакцией** (`Database.transaction`), поэтому не расходятся.
- Это **не полный event sourcing**: состояние нельзя «пересобрать» из журнала. Проще и достаточно.
- Доступ через интерфейсы; SQLite — первый адаптер, PostgreSQL — следующий.

## Альтернативы
Полный event sourcing (состояние = проекция журнала): мощнее, но заметно сложнее; возвращаться к нему можно.

## Последствия
`verify()` проверяет целостность журнала, а не соответствие состояния журналу. Если понадобится такая сверка —
это отдельная проверка (reconcile). Журнал защищён триггерами и цепочкой хэшей (tamper-evident, не tamper-proof).
