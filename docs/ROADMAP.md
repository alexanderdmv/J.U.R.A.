# Roadmap

Принцип: сначала фундамент, который дорого менять потом; потом возможности; самое рискованное — в конце.

## Phase 0 — Фундамент ✅ (этот релиз)
- [x] Контракты и типы (зоны, риск, принципалы, конверт)
- [x] Event Log: append-only, hash-chain, якорь
- [x] Task State Machine, outbox, транзакции
- [x] Policy Engine: default deny, подтверждения, step-up, taint, смена политики только ключом
- [x] Tool Port как единственный путь вызова
- [x] Model Port + Router с жёсткими правилами зон
- [x] Memory Port + SQLite-адаптер
- [x] Vault: зашифрованное хранилище + бумажный код
- [x] Тест на границы слоёв
- [x] ADR-000…006, модель угроз
- [ ] **Решить перед Phase 1:** порядок адаптеров моделей, формат экспорта памяти

## Phase 0.5 — Шифрование и копии ✅ (v0.2)
- [x] Иерархия ключей (ADR-008): главный ключ в Vault, ключи на назначение через HKDF
- [x] Шифрование журнала, названий задач и памяти (AES-256-GCM, привязка к записи, подмена отвергается)
- [x] Целостность журнала проверяется без ключа; открытый текст в зашифрованной базе = ошибка
- [x] Резервные копии одним файлом; восстановление по файлу + бумажному коду; проверка хэшей и якоря
- [x] Сессия и оболочка: пароль один раз; `leak-check` и `peek-raw` — проверить защиту своими глазами
- [x] 161 тест; сквозной сценарий проверен в реальном терминале (init → shell → копия → «кража» → restore)
- [ ] Не сделано: автоматический график копий, копии вне дома (облако), ротация главного ключа, смена пароля/бумажного кода командой

## Phase 0.6 — Работа под паролем ✅ (v0.3)
- [x] Политика с сохранением в зашифрованном хранилище; включение с повторным вводом пароля; `tools`, `policy`, `run`
- [x] Подтверждение рискованных действий в консоли; L3 консоль не подтверждает (нужен Face ID)
- [x] Коннекторы: `http.basic_check` (проверка пароля на сервере), `web.login` (вход через браузер, Playwright)
- [x] Профили сайтов в хранилище (`site add …`); адрес берётся из профиля, не из аргументов
- [x] 208 тестов
- [ ] Не проверено мной: Playwright-драйвер с настоящим браузером (проверка — у тебя)
- [ ] Следующее: OAuth/API-коннекторы (почта, календарь, Spotify, Binance read-only), потому что они надёжнее входа через браузер

## Phase 0.7 — Голос: вход и выход ✅ (v0.4)
- [x] Распознавание GigaAM v3 (локально, процессор), запись push-to-talk, синтез голосами Windows
- [x] `voice-check` (диагностика по пунктам), `listen`, `speak`, `echo`, `listen --remember`
- [x] Аудио не пишется на диск; 245 тестов
- [ ] Не проверено мной: настоящие микрофон, модель и SAPI — проверка у владельца
- [ ] Следующее: измерить скорость на Ryzen 5 2600, проверить английские термины, решить про Piper/Silero

## Phase 0.8 — Укрепление по внешнему ревью ✅ (v0.5)
- [x] P — только локальные модели (облако только для O) до Redaction Gateway — **блокер перед подключением облачных моделей снят**
- [x] `ToolResult` с метками зоны/доверия/источника; `CredentialBroker`; пароли — только после повторного ввода пароля
- [x] Проверка origin при входе через браузер (редирект больше не крадёт пароль)
- [x] Скрытый ввод бумажного кода; `change-passphrase` (с повышением стойкости), `new-recovery-code`; KDF по умолчанию 2^17
- [x] Атомарная замена версии в памяти; тестовые соединения SQLite закрываются (`tests/leak_check.py` → 0)
- [x] Демо-режим и подставные модели убраны из продукта; одна команда установки `pip install -e .` + `python -m jura setup`
- [x] Консоль разнесена на три файла; тест-«сигнализация» на пустой `__init__.py`; 292 теста
- [ ] Отложено осознанно: привязка хранилища к устройству (TPM/Windows Hello/YubiKey) — Phase 2; lock-файл зависимостей — когда голос заработает на твоём ПК
  (`pip freeze > requirements.lock`, не прибивать версии вручную); изоляция сторонних плагинов — ADR-007

- [x] Ключи API через брокер; настройка моделей зашифрована; правила зон при настоящих HTTP-запросах проверены счётом запросов к серверам

- [ ] Следующее: **зоны по источникам** и Redaction Gateway (иначе вся приватная работа — на модели класса 3–4B), бюджеты расходов, потоковый вывод

## Phase 0.10 — Разговор голосом на четырёх языках ✅ (v0.8, ADR-015)
- [x] Распознавание Parakeet v3 (ru/uk/cs/en, язык определяет сама), синтез Piper одним голосом с фонемами по языку каждого куска
- [x] Диалоговое ядро v0 (`runtime/dialogue.py`): история, «отвечай в той же смеси языков», обрезка под окно; `talk`, `chat`
- [x] Личный словарь сленга (`lexicon`, зашифрован); модели подкладываются только прозвучавшие слова
- [x] Контракт модели: `system` + `history` (совместимо), адаптеры Claude/OpenAI/Gemini/локальной
- [x] Локальная модель `jura-gemma3` (gemma3:4b, все слои на GPU: 57 ток/с вместо 8); `setup` её готовит; установщик `--models-dir`
- [x] Проверено на ноутбуке владельца без микрофона: речь → текст → модель → речь ≈ 3 с; 408 тестов
- [ ] Не проверено: живой микрофон и произношение владельца
- [ ] Известно: чешский одним голосом — с акцентом; маленькая модель слабо держит длинный разговор
- [ ] Следующее: автоопределение конца фразы (VAD), потоковый ответ, слово-активатор, перебивание

## Phase 0.10.1 — Перенос на любой компьютер ✅ (v0.8.1, ADR-016)
- [x] Настройки компьютера в `jura.local.json` (`jura config`): J.U.R.A. сам знает, где данные, модели и копии, без переменных окружения
- [x] Установщик для голого Windows: Python с python.org, VC++ Runtime, Git, Ollama — через winget или официальные установщики напрямую
- [x] PATH перечитывается после установки программ; `setup` сам запускает Ollama; `init` подключает локальную модель
- [x] Правило: всё, что не ставит pip, — в `SYSTEM_PACKAGES` или `jura setup`; тест не даст добавить программу без пути для чистого Windows
- [x] Проверено в Windows Sandbox (без Python, Git, winget, VC++)
- [ ] Финальная проверка — на голом Windows 10 владельца; хэши установщиков не закреплены; ярлык на рабочем столе

## Phase 2 — Инфраструктура и зона S
Core-сервер 24/7 (отдельно от повседневного ПК) · автоматические копии + копии вне дома · ротация ключей · mTLS/VPN · ключи устройств · GPU-узел для локальных моделей.

## Phase 3 — Голос по смыслу (начат в v0.8)
~~Диалоговое ядро + голос~~ · ~~Piper~~ · автоопределение конца фразы · перебивание · слово-активатор · узнавание говорящего ·
действия голосом через ToolPort · голос не авторизует L2/L3 · fallback на текст.

## Phase 4 — Почта и календарь
read → draft → act (L2) · scoped-гранты · защита от prompt injection в письмах.

## Phase 5 — Initiative Engine
Standing Orders · A0 → A1 → A2 по доменам · attention budget · kill switch.

## Phase 6 — Финансы: чтение
Банк read-only · биржа read-only · аналитика без права действовать.

## Phase 7 — Финансы: действия
Finance Enclave · подтверждение Face ID на iPhone (passkey: ключ в Secure Enclave подписывает хэш вызова) ·
trade-only sub-account · Risk Engine · лимиты на стороне провайдера.

## Phase 8 — Самоулучшение
Skills и playbooks на проверенном опыте · бенчмарки как ворота · обучение моделей — только потом, на verified данных,
данные зоны S — только локально.

## Сознательно отложено / не делаем
Автономные платежи — запрещены по умолчанию (включение = L3-изменение политики + лимиты у банка) ·
HA-кластер · сложные мультиагентные схемы.
