# Модели: облачные и локальные

Модели — **инструмент, а не основа**: ядро знает только интерфейс `ModelPort`, любую модель можно заменить командой.
Куда можно отправлять данные, решает **роутер**, а не настройки и не сама модель.

## Правила зон (жёсткие, не настраиваются)

| Зона данных | Куда можно отправить |
|---|---|
| **O** — открытое (общие вопросы, публичное) | облачные И локальные модели; побеждает та, у которой выше `quality` |
| **P** — приватное (по умолчанию для всего, что ты вводишь) | **только локальные** (облако — только через Redaction Gateway, его пока нет) |
| **S1** — чувствительное | только локальные |
| **S2** — пароли и ключи | **никому и никогда** |

Явное имя модели (`--model`) эти правила **не обходит**. «Локальная» модель обязана быть на этом же компьютере
(127.0.0.1 / localhost): иначе она могла бы оказаться чужим сервером. Длинный запрос не отправляется модели с маленьким окном
контекста (иначе он молча обрезался бы).

## Команды
```
model discover ПРОВАЙДЕР            показать имена моделей, доступные именно тебе (anthropic | openai | gemini | local)
model add ИМЯ ПРОВАЙДЕР МОДЕЛЬ [--base-url URL] [--context N] [--max-output N] [--quality N]
model list | model remove ИМЯ
model test ИМЯ                      короткий пробный вопрос: работает ли ключ, адрес, имя модели
ask [--zone O|P|S1] [--model ИМЯ] ТЕКСТ    спросить; в ответе видно, какая модель и локально ли
```
Имена моделей меняются часто, поэтому я их **не зашиваю в код**: смотри актуальные через `model discover` и сайт провайдера.

## Облачные (только для зоны O)
```
jura> secret set anthropic.api_key          ← ключ из консоли Anthropic (аналогично openai.api_key, gemini.api_key)
jura> model discover anthropic
jura> model add claude anthropic ИМЯ-ИЗ-СПИСКА --quality 9
jura> model test claude
jura> ask --zone O Объясни, что такое прерывание в процессоре
```
Ключ хранится в зашифрованном хранилище, читается только своей моделью (брокер) и нигде не печатается. **Лимитов расходов пока нет** —
каждый `ask` в облако стоит денег; по умолчанию ответ ограничен 2048 токенами (`--max-output`). У «думающих» моделей рассуждение
тратится из того же лимита: если ответ пустой, увеличь `--max-output`.

## Локальная (для P и S1)
Твоя видеокарта (6 ГБ) тянет модели класса **3–4 млрд параметров**; 7–8 млрд на ней впритык или вообще не помещаются вместе с окном контекста.
1. Поставь **Ollama** (ollama.com, для Windows есть установщик).
2. Выбери небольшую многоязычную модель на ollama.com/library (по обзорам на середину 2026 для 6 ГБ — класс 4B семейства Qwen или Gemma;
   **проверь актуальные названия сам** — я их проверить не мог) и скачай: `ollama pull ИМЯ`.
3. **Окно контекста.** По умолчанию у Ollama оно маленькое (порядка 4K токенов) — длинные тексты теряются. Увеличь через переменную
   окружения `OLLAMA_CONTEXT_LENGTH` (например 8192; проверь по документации Ollama) и перезапусти Ollama; тот же размер укажи в `--context`.
4. В J.U.R.A.:
```
jura> model discover local
jura> model add local-main local ИМЯ-ИЗ-СПИСКА --context 8192
jura> model test local-main
jura> ask --zone P Составь план на завтра: …
```
Сервер LM Studio или llama.cpp тоже подходит: `--base-url http://127.0.0.1:ПОРТ/v1`.

## Честно о главном ограничении
**Всё, что ты вводишь, считается приватным (P)** — значит, пока нет Redaction Gateway, этим займётся только локальная модель класса 3–4B.
Для серьёзной работы с кодом этого мало. Что с этим делать, по порядку:
1. Для действительно открытых вопросов указывай `--zone O` — они пойдут на сильную облачную модель.
2. Следующий шаг — зоны **по источникам** («этот проект открытый», «эта папка — личная») вместо одной зоны на всё (ADR-005, «переопределение владельцем»).
3. Redaction Gateway: очистка приватного контекста и превращение его в новый открытый.
4. Железо: видеокарта с большим объёмом памяти позволит локальную модель на порядок сильнее.

## Если что-то не работает
| Сообщение | Что значит |
|---|---|
| `ключ API отклонён` | неверный/просроченный ключ: `secret set ПРОВАЙДЕР.api_key` заново |
| `адрес или модель не найдены` | неверное имя модели: `model discover …` |
| `превышен лимит запросов или баланс` | закончились деньги или частые запросы |
| `сервер недоступен` (локальная) | Ollama не запущена: запусти её |
| `нет подходящей модели для зоны P …` | нет локальной модели, а облако для P запрещено — это правило, а не поломка |
| `ответ пуст: лимит токенов ушёл на «рассуждение»` | увеличь `--max-output` |
| `запрошена модель '…'` | выбранная модель не подходит под зону запроса |

## Проверено / не проверено
Адаптеры проверены тестами против локальных серверов, отвечающих в формате провайдеров по их документации (запрос, заголовки, разбор ответа,
ошибки, отсутствие утечек ключа, правила зон при настоящих HTTP-запросах). **С настоящими сервисами и с настоящей Ollama они впервые
встречаются на твоей машине** — присылай вывод `model test` и ошибки.
Пока не поддерживаются: потоковый вывод, вызов инструментов самой моделью, учёт расходов.
