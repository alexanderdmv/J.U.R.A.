# Модель угроз (Phase 0 + шифрование)

Одна страница: что защищаем, от кого, чем — и **чего пока нет**.

## Что защищаем
Секреты (пароли, API-ключи, recovery-коды) · деньги и торговые счета · почта, календарь, личные документы ·
исходный код проектов · целостность журнала · сама способность J.U.R.A. действовать только по твоей воле.

## Известные пробелы (не скрываем)
1. **Метаданные видны без ключа:** время, вид события, исполнитель, состояние задач, зона записей памяти, размеры файлов. Файл SQLite целиком не зашифрован. Дополнительно включи шифрование диска (BitLocker).
2. **Офлайн-подбор пароля к украденному `jura.vault`.** Бумажный код для разблокировки НЕ обязателен: хранилище открывается и паролем (scrypt, по умолчанию 2^17 ≈ 128 МБ, ~0,5 с на попытку). Против подбора спасает только очень длинный пароль (фраза из 5+ слов). Настоящая защита — привязка к устройству (TPM / Windows Hello / YubiKey) на Core-машине: Phase 2. `change-passphrase` повышает стойкость у старых хранилищ.
   **Вредоносный код на той же машине**, пока Vault разблокирован, прочитает секреты (Python не стирает память).
   Поэтому Core должен жить на отдельной, не повседневной машине (Phase 2).
3. **Redaction Gateway** (очистка P для облака) не реализован. Поэтому роутер **жёстко** отправляет P только на локальные модели; когда Gateway появится, он должен выдавать очищенный контекст как НОВЫЙ контекст зоны O. Пока локальной модели нет, приватные данные просто не обрабатываются моделью.
4. **Внешний якорь журнала** не автоматизирован: нужно вручную сохранять строку из `verify-log` вне машины.
5. **Ожидающие подтверждения** теряются при перезапуске (безопасно, но неудобно).
6. **Сеть, mTLS, ключи устройств, iOS-подтверждение** — Phase 2–3.
7. **Песочница для кода** — Phase 1 (dev-ассистент).
8. **Потеря и пароля, и бумажного кода = данные потеряны навсегда.** Это свойство, а не баг.

9. **Вход через браузер не проверен с настоящим Playwright** (только с поддельным драйвером). Сайты могут блокировать автоматизацию, показывать капчу или 2FA — это не обходится.
10. **Подтверждение L2 с консоли — уровня DEVICE** (для обычных действий достаточно «да»); для действий с паролями — PASSPHRASE. Для L3 консоль подтвердить не может (нужен Face ID).
10а. **`http.basic_check`: адрес — аргумент вызова**, поэтому защита — твоё подтверждение (в вопросе виден адрес и имя секрета). Для постоянной работы адрес закрепляется в профиле (`web.login`).
11. **Смена политики** пока подтверждается паролем, а не физическим ключом (ADR-003, дополнение).

12. **Голос не проверен с настоящим микрофоном и моделью** (только с подставными). Модель при первом запуске скачивается из интернета — доверие к источнику (Hugging Face) и к пакетам PyPI; закрепление версий и хэшей — позже.
13. **Озвучивание вслух** может раскрыть данные тем, кто рядом. Пока озвучивается только то, что ты сам попросил (`speak`, `echo`); правило «S1 вслух не читать» появится с диалоговым ядром.

14. **Адаптеры моделей не проверены с настоящими сервисами и Ollama** (только с серверами в формате документации). Нет потокового вывода, вызова инструментов и **лимитов расходов**: каждый `ask` в облако стоит денег.
15. **Все данные по умолчанию — P, поэтому обрабатывает их только локальная модель** (на 6 ГБ — класса 3–4B). Это безопасно, но ограничивает возможности, пока нет зон по источникам и Redaction Gateway.

## Правила, которые снижают риск уже сейчас
Не хранить реальные секреты, пока Core живёт на повседневном ПК · реальные деньги не подключать до Phase 6–7 ·
ключи бирж только trade, без права вывода, с IP-whitelist.
